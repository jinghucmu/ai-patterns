What people want from AI is not an answer. It is an answer they can check and act on.

Design patterns for AI products, written down from products I have designed: a way to ask, an index you can jump through, evidence you can open, a mistake you can catch, and the structure underneath that makes the whole thing work for everyone.

The flow every pattern serves

  1. AskThe person has a question, or a thing they want to find.
  2. AnswerThe AI returns something: an excerpt, a marker, a segment, a generated answer.
  3. CheckThe person looks at the evidence and decides whether to believe it.
  4. DecideThe person acts: proceeds, moves on, or corrects the AI.

    Design the whole chain from a person's question to their decision as one flow. Break any link and trust in the AI is hollowed out.

  2. Make the first question pay off

    When an AI needs to learn about a new user before it can help them, ask in a way that produces the first result on the spot, so the person gets value and the system gets context in the same minute.

  3. Each choice narrows the next

    When a person gives the AI several inputs in a row, use each one to make the next easier to give, so the task gets lighter as the system learns.

  8. Match the mode to the question

    Answer in a richer mode (a picture, a recording, a clip) only when it carries something text cannot. For a fact, text wins; for how something works or feels, showing beats telling.

  9. Show the evidence behind the answer

    When an AI answers from a source, return the source with the answer, so the person can open it, read on, and check that it really says what the AI claims.
